# 游戏开发计划

## 目标

根据流程图，将当前可运行原型逐步完善为一款线性探索、生存、战斗和制作游戏。每个阶段必须完成代码实现、运行验证和流程验收后，才能移动到 `docs/已完成事项.md`。

## 当前基础

- 已有 Godot 4.7.2 项目和 1600×900 运行分辨率。
- 已有固定高位俯视镜头、玩家移动、鼠标/手柄朝向、线性地图原型。
- 已有庇护所、三个基站、道路、房屋标记和 HUD 原型。
- 已有菜单、暂停、设置、基础存档和 `Project/items.json` 道具数据表。
- 当前地图、玩家、HUD、背包和道具仍以原型几何体或通用图标为主。

## 流程图对应的核心循环

```text
屋内醒来
  -> 拾取基础武器
  -> 装备武器
  -> 门外出现怪物
  -> 玩家战斗
  -> 光源引导探索
  -> 获取手电、地图和主线提示
  -> 制作并装备手电
  -> 前往第一个基站
  -> 修复基站道路或入口
  -> 获取基站情报
  -> 获得可计时道具
  -> 进入正式生存循环
```

## 开发优先级

### P0：可玩的最小教学闭环

1. **游戏状态和任务状态机**
   - 建立 `GameState`，统一管理新游戏、继续游戏、当前任务、已获得道具、已激活基站和玩家状态。
   - 任务节点至少包含：醒来、拾取武器、装备武器、击败门外怪物、获得手电、到达第一个基站。
   - 验收：新游戏从第一步开始，继续游戏恢复当前任务；任务不会因切换场景丢失。

2. **道具拾取与交互系统**
   - 在房屋内放置基础武器和任务道具。
   - 玩家靠近后显示交互提示，按交互键拾取；道具进入背包并从场景消失。
   - 验收：玩家能够在屋内找到并拾取棒球棍或撬棍，背包数量正确，重复拾取不会重复增加。

3. **装备和快捷栏系统**
   - 背包道具支持装备/使用，快捷栏显示当前装备。
   - 玩家可切换当前武器，角色朝向和攻击系统读取当前武器。
   - 验收：拾取武器后必须装备才能攻击；切换装备后 HUD 和玩家状态同步变化。

4. **基础战斗闭环**
   - 先实现一种近战武器和一种敌人。
   - 加入攻击输入、攻击冷却、攻击范围、伤害、敌人追击、敌人死亡和玩家受伤。
   - 验收：门外敌人出现，玩家可以使用基础武器击败它；玩家死亡后有明确结果并能重新开始。

### P1：流程图中的探索和主线

5. **手电、黑暗和光源系统**
   - 手电作为关键道具，加入开关、电量和光照范围。
   - 夜间或室外危险区域降低可见性，光源影响探索和敌人发现。
   - 验收：完成手电任务后可以打开/关闭手电，手电状态可存档。

6. **地图与主线提示**
   - 地图显示庇护所、玩家、三个基站、房屋和当前目标。
   - 地图和手电图纸作为流程奖励；主线提示明确指向最近目标。
   - 验收：玩家能根据地图和提示找到第一个基站，不依赖编辑器或开发者说明。

7. **房屋搜索和资源掉落**
   - 房屋增加搜索交互、搜索进度和一次性掉落表。
   - 掉落木头、金属零件、电池、食物、弹药和剧情道具。
   - 验收：搜索结果有反馈，离开并重新进入不会重复获得已领取资源。

8. **第一个基站任务**
   - 第一个基站设置为教程目标，加入损坏道路/入口和所需修复材料。
   - 修复后开启基站，显示情报和下一个目标。
   - 验收：基站修复前后路线状态不同，激活状态可存档并影响任务推进。

### P2：正式生存循环

9. **时间、昼夜和基站事件**
   - 实现游戏时间、白天/夜晚和每日 0 点事件。
   - 基站在夜间保持高活跃度，发出求救信号；加入倒计时或信号被摧毁的压力。
   - 验收：时间推进可观察，事件只触发一次或按设计周期触发，存档后时间正确恢复。

10. **制作和图纸系统**
    - 将当前拖拽图纸原型接入配方检查、材料扣除和成品生成。
    - 支持手电、武器、消耗品和机器人基座的最小配方。
    - 验收：材料不足时不能制作；材料足够时制作成功并写入背包和存档。

11. **三基站线性区域推进**
    - 三个基站分别解锁区域、情报和新制作内容。
    - 通过道路、门、敌人或材料形成线性推进，而不是单纯走到标记点。
    - 验收：基站 1、2、3 具有不同功能，顺序推进明确。

12. **完整存档和失败流程**
    - 存档玩家位置、生命、体力、装备、背包、任务、基站、房屋搜索和时间。
    - 增加死亡、重试、回到庇护所和保存退出流程。
    - 验收：退出重进后核心进度完整恢复，死亡不会损坏存档。

### P3：表现和内容扩展

13. **正式美术替换**
    - 替换通用图标、几何体地图、玩家球体和文字标记。
    - 统一 Darkwood/阿瑞斯病毒方向的低饱和手绘视觉语言。

14. **音效和反馈**
    - 加入拾取、攻击、受伤、搜索、基站、敌人警戒和环境音。
    - 加入命中闪烁、伤害数字、交互反馈和任务完成提示。

15. **内容扩展**
    - 增加枪械、弹药、食物、机器人、更多敌人、房屋类型和剧情日志。

## 每一步的固定验收流程

1. 修改前确认本阶段目标和验收标准。
2. 实现一个可独立测试的最小功能。
3. 使用 Godot 4.7.2 加载相关场景并运行检查。
4. 检查脚本解析、资源引用、场景信号和存档兼容性。
5. 记录验证命令和结果。
6. 通过后从 `进行中事项.md` 移到 `已完成事项.md`。
7. 再开始下一阶段，不把未验收功能标记为完成。

## 体量与时间设计

- 目标流程时长：3-5 小时。
- 游戏内时间：21 天。
- 每天现实时间：约 10-14 分钟，其中白天 8-10 分钟、夜晚 3-5 分钟。
- 推荐完整可探索范围：约 320×240 Godot 单位；第一阶段垂直切片先使用约 80×60 单位。
- 推荐玩家速度：普通移动 5.5，奔跑 8.5；道路正常移动，森林和废墟减速 10%-25%。
- 地图内容：1 个庇护所、3 个基站、1 个最终区域、18-25 个可搜索房屋、6-10 个特殊地点。

## 道具投放规则

- 关键道具固定投放，避免随机掉落导致流程卡死。
- 普通资源半随机投放，使用每类房屋的资源池和数量范围。
- 庇护所周围投放食物、木头和基础武器；第一基站投放金属零件、电池和绳子；第二基站投放弹药和枪械素材；第三基站投放高级材料和图纸；最终区域投放日志和剧情道具。
- 普通民房、工具房、军械库和研究所使用不同掉落表。
- 房屋资源只能领取一次，并写入存档。

## 地图推进规则

- 庇护所是安全起点和建造中心。
- 三个基站按顺序推进，每个基站解锁地图、任务或制作内容。
- 区域之间通过道路、门、断路、敌人和材料需求限制通行。
- 第一阶段先完成庇护所、一个房屋、一个敌人、一个基础武器、一个小型基站和一次夜间防守的垂直切片。
